# Хостинг

## Коротко

Есть два честных варианта, и выбор между ними — не про технологию, а про то,
согласны ли вы платить €4 в месяц.

| | Бесплатно: Vercel + Neon | ~€4/мес: маленький VPS |
| --- | --- | --- |
| Изменения в коде | webhook вместо polling, Postgres, FSM в БД | никаких |
| Отклик бота | 1–3 с на холодном старте | мгновенный |
| Надёжность | зависит от двух чужих бесплатных тарифов | зависит от вас |
| Сложность | заметная | `docker compose up` |

Если бесплатность — жёсткое требование, берите первый. Если четыре евро в
месяц приемлемы, второй проще, быстрее и не требует ничего переписывать.

## Почему Vercel не работает «как есть»

Три препятствия, и все настоящие.

**Бот использует long polling.** Он держит открытое соединение с Telegram и
ждёт. На Vercel нет долгоживущих процессов: функция просыпается на запрос и
умирает. Polling там невозможен в принципе. Нужен webhook — Telegram сам
стучится в ваш URL на каждое сообщение.

**SQLite не переживает деплой.** Файловая система функции эфемерная. База
должна быть внешней; Neon даёт бесплатный Postgres, а приложение уже умеет с
ним работать через `DATABASE_URL` с `asyncpg`.

**Состояние диалогов терялось бы между сообщениями.** aiogram по умолчанию
хранит незавершённые диалоги в памяти процесса. На serverless каждое сообщение
может попасть в новый экземпляр, поэтому бот забывал бы выбранную дату до того,
как вы введёте текст задания. Ломались бы все многошаговые сценарии: домашка,
приглашения, замены, события, расписание.

Это уже исправлено: `app/fsm_storage.py` хранит состояние в той же базе, что и
данные. Побочная польза — редеплой больше не обрывает начатые диалоги. Покрыто
11 тестами, включая проверку, что новый экземпляр подхватывает диалог старого.

## Вариант 1: Vercel + Neon

### Что нужно

1. Аккаунт [Neon](https://neon.tech) — бесплатный Postgres.
2. Аккаунт [Vercel](https://vercel.com), Hobby-тариф.
3. Токен бота от [@BotFather](https://t.me/BotFather).
4. Ваш Telegram id от [@userinfobot](https://t.me/userinfobot).

### Секреты

**Никогда не отправляйте токен в переписку, в коммит или в issue.** Токен даёт
полный контроль над ботом: читать все сообщения, отвечать от его имени, менять
его. Утёкший токен отзывается в @BotFather командой `/revoke`.

Правильное место — переменные окружения хостинга. В Vercel:
**Settings → Environment Variables**, и обязательно отметьте `Sensitive`, иначе
значение можно будет прочитать в интерфейсе.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | токен от BotFather |
| `OWNER_IDS` | ваш Telegram id |
| `DATABASE_URL` | строка подключения Neon, схема `postgresql+asyncpg://` |
| `TIMEZONE` | часовой пояс по умолчанию для новых классов |
| `WEBHOOK_SECRET` | случайная строка, см. ниже |
| `RUN_BOT` | `false` — polling на serverless не запускается |

`WEBHOOK_SECRET` придумайте сами и никому не показывайте:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

Telegram присылает его в заголовке `X-Telegram-Bot-Api-Secret-Token` на каждом
запросе. Без проверки этого заголовка ваш webhook-адрес — открытый эндпоинт, в
который кто угодно может слать поддельные апдейты: назначить себя редактором,
переписать расписание, стереть домашку. Проверка обязательна.

### Строка подключения Neon

Neon выдаёт `postgresql://user:pass@host/db?sslmode=require`. Приложению нужен
асинхронный драйвер, поэтому замените схему:

```
postgresql+asyncpg://user:pass@host/db
```

`?sslmode=require` уберите: asyncpg такого параметра не понимает и падает на
старте. TLS он и так использует по умолчанию для внешних хостов.

### Регистрация webhook

Один раз после деплоя:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://<ваш-проект>.vercel.app/api/v1/telegram/webhook" \
  -d "secret_token=<WEBHOOK_SECRET>" \
  -d "drop_pending_updates=true"
```

Проверить: `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`. Поле
`last_error_message` покажет, почему Telegram не может достучаться.

Эту команду выполняете вы, у себя, — токен в ней открытым текстом.

### Чего ожидать

Первое сообщение боту после простоя обрабатывается 1–3 секунды: холодный старт
Python-функции плюс подключение к Neon. Дальше быстро, пока экземпляр живой.
Для дневника терпимо, но это не мгновенный отклик обычного бота.

## Вариант 2: свой сервер

Ничего переписывать не нужно — код уже так работает.

```bash
git clone https://github.com/lumenpearson/lessons && cd lessons
cp server/.env.example server/.env    # впишите BOT_TOKEN и OWNER_IDS
docker compose up -d --build
```

`docker-compose.yml` поднимает Postgres и приложение. Бот работает через
polling, поэтому внешний адрес и webhook не нужны вообще — сервер может стоять
за NAT без белого IP.

Приложению на телефоне нужен доступ к API. Варианты: белый IP с пробросом
порта, туннель вроде Cloudflare Tunnel, или, если все ученики в одной школьной
сети, просто локальный адрес.

Подойдёт любой VPS с 1 ГБ памяти. Нагрузка одного класса — это несколько сотен
запросов в день.

## Что выбрать

Для одного класса и одного человека, который это поддерживает, **VPS проще**:
меньше движущихся частей, нет холодных стартов, не зависит от чужих бесплатных
тарифов, которые меняются.

**Vercel + Neon** оправдан, если платить нельзя или если классов станет много и
захочется не думать про сервер вообще.
