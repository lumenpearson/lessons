# edu.tatar.ru — «Электронное образование в Республике Татарстан»

*Part of [the electronic diaries of Russia’s regions](../diaries.md). Verification: extracted, checked against the code, and dated. Confidence of the whole: medium. Nothing here has been tried against the live service.*

**The old diary of Татарстан, retired for pupils and parents in January 2024**, when the republic
moved to the МЭШ-based [«Моя школа»](mesh-myschool.md) at `ms-edu.tatar.ru`. It is on this page
because it ran for fifteen years and its clients are still on GitHub, not because a new client
should be written against it.

**It never had an API.** Every route below is a server-rendered page that hobby bots scraped by
CSS class or regular expression, behind a `DNSID` session cookie from a form login whose field
names changed around 2021. The rows describing the new system at `ms-edu.tatar.ru` are the
МЭШ family API and belong to [«Моя школа»](mesh-myschool.md) in substance; they are kept here
only where a Татарстан client names them.

**Signing in.**

*edu.tatar.ru login/password form (legacy, until January 2024)* — token carried as cookie DNSID. Lifetime: server session; clients observed it expiring and re-sign in on demand, several re-sign in before every read. Refresh: no refresh endpoint; repeat POST /logon. autologin=1 (mrUmnik) plausibly sets the persistent HLP cookie (seen in a copied browser Cookie header as '<user id>\|<bcrypt hash>').

1. Optional: GET https://edu.tatar.ru/logon to receive initial cookies (DNSID, _xsrf on .tatar.ru)
2. POST https://edu.tatar.ru/logon as application/x-www-form-urlencoded with main_login2=<login>&main_password2=<password> (newer form, 2021+) or main_login=<login>&main_password=<password>[&autologin=1] (older form, to ~2020); Referer https://edu.tatar.ru/logon (or /login/ or /start/logon), Origin https://edu.tatar.ru, a desktop or mobile browser User-Agent
3. Follow redirects; success = page contains «Мой дневник» or «Личный кабинет»; failure = page stays on /logon with div.alert.alert-danger «Неверный логин или пароль» or «Доступ в систему временно заблокирован» (after repeated failures), or redirect to /message
4. Keep the DNSID cookie and send it on every request (Cookie: DNSID=<value>)
5. When a page shows the sign-in form («Выберите дальнейшее действие», «Войти в учётную запись EDU») or «Пользователь не найден», or the effective URL path is /logon, sign in again and repeat the request

   Accounts with two-factor authentication enabled cannot sign in this way (ruslankhayrut/Ponchikkk error text asks to switch 2FA off). Alternative endpoints POST /login and POST /logon/ accept the same fields. Retired for pupils and parents in January 2024: the diary moved to ms-edu.tatar.ru, where «Вход в региональную систему как для родителей, так и для учеников возможен только через портал госуслуг РФ» (tatar-inform, 10.01.2024). WebFetch of https://edu.tatar.ru/, /logon and /login/ on 2026-09-24 answered HTTP 404 (fetcher-side, possibly geo-blocking; not conclusive about the host's state).

   a separate page /admin/auth/logon exists; ClienD-ext redirects from it to the main sign-in; last client evidence 2023 (ruslankhayrut archived April 2023, Ponchikkk January 2023); whether school sites and their admin still live on edu.tatar.ru after 2024 is not established

*ms-edu.tatar.ru («Электронное образование РТ» on МЭШ, current since January 2024) — ESIA only, through the regional AUPD* — token carried as header Authorization: Bearer <JWT> (+ Profile-Id); web API also cookie aupd_token. Lifetime: not stated in the sources. Refresh: POST /v3/token/refresh (refresh_token form field); profile token via GET /v2/token/refresh.

1. Credentials are Госуслуги (ESIA) only, for pupils and parents alike: an adult or a pupil aged 14+ uses a verified personal Госуслуги account; a pupil under 14 uses a simplified child account the parent creates in «Семья и дети» on Госуслуги, signing in with that child account's login and password at ESIA. There is no regional login/password form (tatar-inform 10.01.2024; МЭШ help page «Авторизация для учащихся и родителей в регионах»; OctoDiary v4 offers only ESIA in-browser/WebView or a pasted school token for Tatarstan)
2. Generate a state UUID (v4)
3. Open in an in-app browser GET https://ms-edu.tatar.ru/v3/auth/esia/login?redirect_url=<app deep link authRegionRedirect>&state=<uuid> (kauth instead of esia for the non-ESIA option); the region config has authBaseUrl prod = https://ms-edu.tatar.ru
4. The user signs in at esia.gosuslugi.ru; the browser returns to redirect_url with ?code=<code> (or ?error=accountDoesNotExist / accountIsNotComplete)
5. GET https://ms-edu.tatar.ru/v3/auth/token?code=<code>&state=<uuid> → JSON {token, refreshToken}; the JWT must carry a role
6. Per profile: GET https://ms-edu.tatar.ru/v2/token/refresh?subsystem=2&roleId=<1 student\|2 parent> with Authorization: Bearer <aupd token> → 201, body is the profile token
7. API calls to https://ms-edu.tatar.ru/api/family/mobile/v1/... carry Authorization: Bearer <token> and Profile-Id: <id> (some also Auth-Token: <token>)
8. Refresh: POST https://ms-edu.tatar.ru/v3/token/refresh, application/x-www-form-urlencoded refresh_token=<…> → 201 JSON {access_token, refresh_token}
9. Logout: https://esia.gosuslugi.ru/idp/ext/Logout?client_id=MS-EDU&redirect_url=<https://ms-edu.tatar.ru/v3/redir?url=<deep link>>
10. fgis-dnevnik-desktop (Electron) opens https://ms-edu.tatar.ru/v3/auth/esia/login and takes the token from the aupd_token cookie, a Set-Cookie header or a token=/access_token= URL parameter; it then sends Authorization: Bearer <token>, Cookie: aupd_token=<token>; aupd_current_role=2:1, x-mes-subsystem: familyweb

   From the official «Моя Школа»/«Дневник МЭШ» app (decompiled in AmetistYT/mesh_expressive, region rgn 16 config: authBaseUrl/apiSchoolUrl https://ms-edu.tatar.ru, apiMapiUrl https://ms-edu.tatar.ru/api/family/mobile + /v1, apiBaseUrl https://school-edu.tatar.ru; ESIA logout client_id MS-EDU) and from fgis-dnevnik-desktop. The non-ESIA /v3/auth/kauth/login is built by the app when the ESIA flag is off but is not offered for Tatarstan. Pupil app «Я — школьник», parent app «Дневник. Моя школа» (tatar-inform). OctoDiary's MesTatarstanAuthGateway is all TODO; its accepted token format for Tatarstan is the 'School' token.

**Headers the clients send.**

| Header | Value | Why |
| --- | --- | --- |
| `User-Agent` | a real browser string | every client sends one; some rotate from a list, one uses a mobile Chrome (Nexus 5) UA |
| `Referer` | https://edu.tatar.ru/logon | sent with the sign-in POST by nearly every client (variants /login/, /start/logon, bare https://edu.tatar.ru) |
| `Origin` | https://edu.tatar.ru | sent with the sign-in POST by most clients |
| `Content-Type` | application/x-www-form-urlencoded | form posts |
| `Cookie` | DNSID=<session> | session carrier on every authenticated page |
| `Profile-Id` | <profile id> | ms-edu.tatar.ru /api/family/mobile calls (official app createAuthHeaders), with Authorization: Bearer |
| `x-mes-subsystem` | familyweb | ms-edu.tatar.ru /api/family/web calls in fgis-dnevnik-desktop |

**Captcha and second factor.** edu.tatar.ru (legacy): no captcha handling in any client; the portal could block an account temporarily after failed attempts («Доступ в систему временно заблокирован»), and accounts with two-factor authentication enabled could not use the form sign-in. ms-edu.tatar.ru (current): every sign-in goes through ESIA in a browser, so Госуслуги's own confirmation steps (SMS/app code, captcha where ESIA asks for one) happen there; no client automates them, and none can sign in headlessly.

Clients route through proxies (Aqendo PROXY env; Str1kez notes aiohttp proxy did not work for the site; gerdoe-jr retries until HTTP 200 with 120 s timeouts; DEREWER sleeps 3–5 s between public pages). mrUmnik disables TLS verification. Success markers differ per client: «Мой дневник» (Aqendo), «Личный кабинет» (ruslankhayrut, Ponchikkk, ClienD-ext), «Выход» (gerdoe-jr); evildes reads the _xsrf cookie after GET /logon but never sends it. Current state (2026): the only live sign-in for the Tatarstan diary is ESIA via https://ms-edu.tatar.ru/v3/auth/esia/login; everything on edu.tatar.ru is the pre-2024 generation.

**Formats.**

- *Dates*: Day and week pages take a unix timestamp in seconds of local midnight in Moscow time (UTC+3): /user/diary/day?for=1664917200 is 5 Oct 2022; /user/diary/week?date=<ts>. Pages print dates as «5 Окт 2022» (abbreviated Russian month, «Мая» for May) and the XML diary uses Russian month names in page/@month and day-of-month in day/@date. News dates are dd.mm.yyyy. ms-edu.tatar.ru family API dates are YYYY-MM-DD.
- *Ids*: Login is a numeric account number (examples in READMEs are 9–10 digits); session DNSID is 40 hex characters; school_subject_id, news_block_id, simple page ids and organization ids (org1505) are integers
- *Pagination*: none for the diary: navigation is by date (prev/next day links day?for=<ts>, prev/next week a.g-button-blue); term via term=1..4\|year; admin page lists paginate through .pages links (?page=); ms-edu.tatar.ru family API takes from/to ranges
- *Notes*: Everything on edu.tatar.ru except /user/diary.xml and the CKFinder connector is HTML, parsed by CSS classes: d-date, table.main, table.marks, term-marks, tt-days, tt-days-mo, tt-subj, tt-task, tt-mark, tt-separator, tableEx, week-selector. Marks are digits 1–5, 'н' absent, 'б' ill; averages like 4.50. ms-edu.tatar.ru answers JSON (МЭШ shapes).

**Caveats.**

- edu.tatar.ru has no API: every route is an HTML page scraped by CSS class or regex, reverse-engineered by hobby bots; the only structured responses are /user/diary.xml (seen in one 2017 client) and the CKFinder XML.
- The sign-in form changed field names from main_login/main_password to main_login2/main_password2 around 2021; which set a given date accepts is inferred from client dates only.
- Routes still marked uncertain on edu.tatar.ru (/user/news, /start/logon-process, wifiauth /login.html) rest only on commented-out code or markup; the other fixture-only routes are links of the real pre-2024 portal and are marked legacy.
- Teacher journal and school-site admin routes come from a browser extension (URL match patterns) and two menu-uploading scripts; the journal's own Ajax endpoints for setting marks are not visible in any source.
- Some repositories hard-code credentials or tokens (DClassRu test_data.py, rkoshelev Cookie header, akayumeru fixture, ClienD VK token); they are redacted here.
- WebSearch budget was exhausted (also during this currency check); discovery relied on GitHub repository search pages, a Sourcegraph index that had no hits, and pages fetched directly.
- ms-edu.tatar.ru is known from two sources: the decompiled official app (region-16 hosts and the regional AUPD sign-in; the family-mobile paths are the app's generic МЭШ calls composed on the regional host, not Tatarstan-specific code) and fgis-dnevnik-desktop (a generic multi-region client). OctoDiary's Tatarstan gateway is still all TODO.
- The official app's /v3/auth/sudir/auth (POST {mos_access_token}) is the Moscow SUDIR path and is not used for Tatarstan; school-edu.tatar.ru is configured but no route was seen against it.
- The decompiled getAuthURL reads "" + authBaseUrl \|\| schoolUrl + "/v3/auth/" + type + "/login"; the parenthesisation was lost in decompilation — fgis-dnevnik-desktop's https://{domain}/v3/auth/esia/login confirms the intended URL.
- Generations: edu.tatar.ru is the pre-2024 generation and every route on it is legacy; ms-edu.tatar.ru (МЭШ-based, ESIA-only) has been the diary since January 2024 (tatar-inform 10.01.2024; МЭШ help page fetched 2026-09-24). No edu.tatar.ru client was ported: DClassRu's Feb 2024 merge from a branch named ms-edu-tatar still only drives https://edu.tatar.ru/login/, and Str1kez/marks_bot declared itself deprecated on 2023-12-02.
- Whether the non-diary parts of edu.tatar.ru (school websites, /admin/page/*, CKFinder storage, the public directory, the teacher journal) outlived 2024 is not established: WebFetch of https://edu.tatar.ru/, /logon and /login/ on 2026-09-24 returned HTTP 404 (possibly the fetcher being blocked), the Wayback CDX API was offline, and the WebSearch budget was exhausted. They are marked legacy on the strength of the last client evidence (2023) and the platform change.
- The ms-edu.tatar.ru rows duplicate the mesh_myschool platform kind: /api/family/mobile/v1/* and /v3/auth/* are the generic МЭШ calls that the official app composes on Tatarstan's hosts. The fgis-dnevnik-desktop rows (/api/family/web/v1/*, /api/ej/rating/*, /api/materials/*, /api/food/*) are uncertain because that client builds every URL from a region table mostly generated in one commit and describes petersburgedu.ru and school.mos.ru as gateways of the same API; nothing shows these paths were exercised against ms-edu.tatar.ru.
- The official app's rgn-16 dev and test hosts are Moscow's (dnevnik-dev-k8s.mos.ru, dnevnik-test.mos.ru, school-dev.mos.ru, school-test.mos.ru); they are not Tatarstan instances.
- No vendor documents an API for edu.tatar.ru or ms-edu.tatar.ru; nothing could be added from official documentation.
