# Дневник.ру — the federal platform

*Part of [the electronic diaries of Russia’s regions](../diaries.md). Verification: extracted, checked against the code, and dated. Confidence of the whole: medium. Nothing here has been tried against the live service.*

**The one platform with a documented API, and a documentation nobody can read any more.**
`api.dnevnik.ru` is a partner REST API under `/v2` (also spelt `/v2.0`); its Swagger answers 404
today, and the 169 operations it described were read from the Wayback Machine's copy of
February 2021. The 259 rows below are that copy joined with what the clients actually call —
167 current, 70 legacy, 22 seen once. The token travels in an `Access-Token` header.

**Signing in has moved to Госуслуги in most of its regions.** Each region has its own ЕСИА
entry (`login.dnevnik.ru/login/esia/<region>`), and in those regions no login and password
exist to post. The clients get a token three ways: a scripted form login followed by the OAuth2
implicit grant under a third party's `client_id` — which Дневник.ру can revoke at any time —
the official partner code grant, or a person signing in in a browser and the client copying the
`DnevnikAuth_a` and `DnevnikAuth_l` cookies. The login form showed a captcha to an anonymous
fetch on 24 September 2026, and no client solves one.

**The Московская область brand is history.** `school.mosreg.ru` was Дневник.ру under another
name until 1 September 2023, when the region moved to [«Моя школа»](mesh-myschool.md); its
rows are kept and marked legacy, because the same paths still answer on `api.dnevnik.ru`.

**Signing in.**

*OAuth2 implicit grant driven by a scripted form login (the way every Python client gets a token)* — token carried as header Access-Token (kesha1225, SiroXYZ, C#, Java, JS clients; pixwet spells it Access-token); query parameter access_token (WebMad/edubot_vk PHP bot, w00lf Ruby gem). Lifetime: Not stated anywhere; clients treat it as long-lived and store it. pixwet/mosreg's regex shows it is exactly 32 characters (hex, no dashes).. Refresh: None. Re-run the login flow. pixwet's v2/authorizations model carries grant_type and refreshToken fields but no client exercises a refresh..

1. POST https://login.dnevnik.ru/login/ with ReturnUrl, login, password. pydnevnikruapi (kesha1225) sends all three as QUERY parameters (aiohttp params=); paracosm17/dnevnikru and I-or-not-I send login/password as a form body (data=). ReturnUrl = https://login.dnevnik.ru/oauth2?response_type=token&client_id=<client_id>&scope=<scopes>[&redirect_uri=…]. Follow redirects.
2. If the final URL's query does not carry result=success, request the ReturnUrl again with the session cookies: kesha1225 0.2.0 POSTs it, pixwet GETs it (SiroXYZ tocken.py instead GETs https://login.dnevnik.ru/login/?ReturnUrl=… with copied cookies). The consent has already been granted for these client_ids, so the redirect ends on a URL whose fragment is #access_token=<32 chars>&state=. The landing page https://…/oauth2/Authorization/Result?response_type=token&client_id=…&scope=…&is_granted=False&result=success is evidenced only on login.school.mosreg.ru (pixwet regex).
3. Where consent has not been granted, submit it: POST https://login.dnevnik.ru/oauth2/?access_token=0&response_type=token&client_id=…&scope=… with form fields access_token=0, response_type=token, client_id, scope, is_granted=true and the session cookie; the token is in the redirect's fragment (WebMad/edubot_vk AuthOperation::getDnevnikAccessToken reads it from the raw Location header).
4. Take access_token from the URL FRAGMENT. kesha1225 slices fragment[13:-7] (strips 'access_token=' and '&state='); pixwet/mosreg matches ^…#access_token=(.{32})&state=$ ; SiroXYZ token-auto-dnevnik.ru splits on 'access_token=' then '&'. If the HTTP status is not 200 the clients report «Сайт лежит или ведутся технические работы».
5. Alternative without password (SiroXYZ/DnevnikRuAPI_NEW tocken.py, for regions where the web login is Госуслуги-only): log in in a browser, copy cookies DnevnikAuth_a and DnevnikAuth_l from https://login.dnevnik.ru/auth, then GET https://login.dnevnik.ru/login/?ReturnUrl=<oauth2 url> with those cookies and read the fragment as above.
6. Manual variant documented by yasg1988 and SiroXYZ: sign in at https://login.dnevnik.ru/login, open https://login.dnevnik.ru/oauth2?response_type=token&client_id=<redacted>&scope=CommonInfo,EducationalInfo , press «Разрешить», copy access_token from the address bar.

   client_ids seen: <redacted> (pydnevnikruapi ≤0.1.1, SiroXYZ, vloldik Android app; scope CommonInfo,ContactInfo,FriendsAndRelatives,EducationalInfo), <redacted> (pydnevnikruapi 0.2.0, yasg1988; scope CommonInfo,EducationalInfo), <redacted> = <redacted> (login.school.mosreg.ru; scope CommonInfo,ContactInfo,FriendsAndRelatives,EducationalInfo,SocialInfo). Official scope list: CommonInfo, ContactInfo, FriendsAndRelatives, EducationalInfo, SocialInfo, Files, Wall, Messages. pykpt/smapi additionally posts exceededAttempts=False, Captcha.Input='', Captcha.Id='' to the mosreg login form — the form has a captcha after repeated failures. pixwet's default mosreg ReturnUrl uses client_id <redacted> with scope EducationalInfo,CommonInfo,FriendsAndRelatives,SocialInfo,ContactInfo, but its success regex expects client_id <redacted>&scope=EducationalInfo. WebMad posts exceededAttempts=false too, and uses its own DNEVNIK_CLIENT_ID from .env with scope Avatar,FullName,Schools,EduGroups,Lessons,Marks,Relatives,Roles,EmailAddress,Birthday,Messages. CURRENCY (2024–2026): kesha1225/DnevnikRuAPI issue #16 (open, 2024-09-24): «В нынешних реалиях зайти лог+пасс нереально, т.к. дн.ру форсит госуслуги»; the live form (2026-09-24) shows a captcha to an anonymous fetch. The scripted form login only works for accounts that still have a Дневник.ру password and no captcha challenge; kesha1225 0.2.0 (2025-10-16) still implements it, but the newest tools moved to the interactive variant below.

*Interactive browser implicit grant (the current way for accounts that sign in through Госуслуги)* — token carried as header Access-Token. Lifetime: not stated; clients store it and reuse it. Refresh: none in the implicit grant; repeat the browser step.

1. Open in the user's browser https://login.dnevnik.ru/login/?ReturnUrl=<urlencoded https://login.dnevnik.ru/oauth2?response_type=token&client_id=<id>&scope=CommonInfo,ContactInfo,FriendsAndRelatives,EducationalInfo&redirect_uri=<your callback>>.
2. The user signs in by password + captcha or through «Войти через Госуслуги» (/login/esia/{slug}); Дневник.ру then redirects to redirect_uri#access_token=<token>&state=…
3. A callback page reads access_token from the fragment (SiroXYZ/token-auto-dnevnik.ru templates/callback.html, app.py /callback); without redirect_uri the user copies the token from the address bar (the manual variant documented by yasg1988 and SiroXYZ).
4. Use it in the Access-Token header against https://api.dnevnik.ru/v2/…

   SiroXYZ/token-auto-dnevnik.ru (last commit 2025-12-17) with client_id <redacted> (<redacted> in its README) and redirect_uri http://localhost:8000/callback; SiroXYZ/DnevnikRu_proxiAPI (2026-05-30) takes the resulting token. This is the only token path in the corpus that survives an ЕСИА-only account without handling Госуслуги credentials.

*OAuth2 authorization-code grant (official partner flow)* — token carried as header Access-Token or query access_token. Lifetime: Finite and reported by the server: Authorization.expiresIn («время до окончания действия токена», int64) in the token response; the value is not recorded anywhere in the corpus.. Refresh: Documented: POST /v2.0/authorizations with grant_type=RefreshToken and refreshToken (TokenRequest in the official Swagger); no client exercises it..

1. Redirect the user to https://login.dnevnik.ru/oauth2?response_type=code&client_id=<id>&scope=<comma list>&redirect_uri=<uri>&state=<state> (response_type=token puts access_token in the fragment instead: redirect_uri#access_token=<token>&state=<state>).
2. Receive ?code=… on redirect_uri.
3. Exchange it: POST https://api.dnevnik.ru/v2.0/authorizations (official Swagger v2.0, Authorizations_PostTokenRequestCode «Обменять код доступа на токен») with body TokenRequest {code, client_id (uuid), client_secret (uuid), grant_type: AuthorizationCode, refreshToken}. Response Authorization {accessToken, expiresIn, expiresIn_str, refreshToken, scope, user, user_str}. Older forms: POST /v1/authorizations (w00lf gem, 2015); POST api.school.mosreg.ru/v2/authorizations form-encoded (pixwet, retired host).
4. Use the token in Access-Token.

   The only archived copy of the official Swagger is https://web.archive.org/web/20210225084600/https://api.dnevnik.ru/partners/swagger/docs/v2.0 (2021-02-25); the live Swagger UI renders only a 'Partners API' heading and the JSON docs paths 404. Needs a registered partner client_id/client_secret.

*ЕСИА (Госуслуги) sign-in* — token carried as header Access-Token (from authorization.accessToken of the ЕСИА flow or after an OAuth hop); cookies DnevnikAuth_a / DnevnikAuth_l / t0 for the browser variants. Lifetime: authorization.expiresIn in the ЕСИА response (value unknown). Refresh: refreshToken in the response; refresh documented via POST /v2.0/authorizations grant_type=RefreshToken.

**Headers the clients send.**

| Header | Value | Why |
| --- | --- | --- |
| `Access-Token` | <access_token> | Bearer for every api.dnevnik.ru / api.school.mosreg.ru call (v1, v2, v2.0, mobile/*). Case-insensitive; pixwet sends 'Access-token', proxiAPI README shows 'access-token'. |
| `Accept` | application/json | Set by the C# and proxiAPI clients; without it an error can come back as an HTML error page (clients parse <div class="error__description">). |
| `Content-Type` | application/json | POST bodies are JSON (pydnevnikruapi json=, dnevnik-js, C#, proxiAPI). Exception: pydnevnikruapi PUT and the vloldik Android app send form-encoded bodies. |
| `User-Agent` | a desktop browser string (paracosm17: Chrome/94 on Linux; token-auto-dnevnik.ru: Chrome/126 on Windows; pixwet: fake_useragent random) | Login form and legacy pages; not required by the JSON API. |
| `Referer` | the page URL being fetched, or https://dnevnik.ru/userfeed | schools.dnevnik.ru scrapers set it; not required by the JSON API. |

**Captcha and second factor.** The login form at https://login.dnevnik.ru/ showed a captcha («Введите символы с картинки») to an anonymous fetch on 2026-09-24; older clients post empty Captcha.Id / Captcha.Input / exceededAttempts (pykpt/smapi; WebMad exceededAttempts=false), i.e. it used to appear only after repeated failures. No client solves it. Госуслуги 2FA is handled by nobody: the documented partner ЕСИА flow leaves the Госуслуги step to the user's browser, and dnevnikru-aio's playwright automation has 2FA as a TODO.

Rate limits: the official error list has ApiRequestLimit («превышен лимит запросов для данного токена»); SiroXYZ/DnevnikRu_proxiAPI observed HTTP 429 and HTTP 433 and retries 5 times with 0.3 s × attempt back-off, caps concurrency at 10 and sleeps 1.5 s after every 100 requests. Error envelope: JSON {type, description} with type in camelCase — apiUnknownError, apiServerError, parameterInvalid, authorizationFailed, invalidToken, plus the thirteen official types (invalidRequest, parameterInvalid, apiResourceUnavailable, apiMethodNotSupported, apiRequestLimit, apiServerError, apiHttpsRequired, authorizationInvalidToken, authorizationTokenRequired, authorizationOutOfScope, authorizationNotOwner, authorizationOwnerForbidden, authorizationSystemForbidden); pixwet also accepts short forms (invalidToken, tokenRequired, outOfScope, notOwner, ownerForbidden, systemForbidden, resourceUnavailable, methodNotSupported, requestLimit, serverError, httpsRequired). HTTP 503 / 405 mean maintenance (C# client). pykpt/smapi (mosreg) cannot send any request that carries a body, query params or v='': its @processing wrapper takes one positional argument. Token response fields (official Swagger): accessToken, expiresIn, refreshToken, scope, user. Every documented operation takes the header Access-Token ('OAuth2 token') and states its scope in the description («Права доступа: EducationalInfo», «Files», …).

**Formats.**

- *Dates*: Path and query dates are ISO: yyyy-MM-dd for day-granular routes (marks/{from}/{to}, lessons/{from}/{to}, homeworks startDate/endDate in SiroXYZ) and yyyy-MM-ddTHH:mm:ss for schedules (startDate=…T00:00:00, endDate=…T23:59:59); kesha1225 passes datetime.isoformat() (with microseconds) everywhere and the server accepts it; the C# client sends round-trip 'o' format. Responses: lesson.date is yyyy-MM-ddTHH:mm:ss, mark.date and work.sentDate carry microseconds (yyyy-MM-ddTHH:mm:ss.ffffff), reporting-period start/finish are datetimes (clients slice [:10]). Legacy .aspx pages use dd.MM.yyyy. Naive local times, no zone; users/me has a timezone field.
- *Ids*: 64-bit integers that exceed JavaScript's safe range, so every entity also carries a string twin: id / id_str, personId / personId_str, userId / userId_str, lesson / lesson_str, work / work_str, person / person_str, eduGroup / eduGroup_str. Use the *_str form when building URLs from JS; Python clients use ints. 'me' is accepted in place of a user id on users/… routes. personId (person) and userId (account) are different objects and both appear in context. Teacher and timetable payloads use PascalCase keys (Id, FirstName, ShortName, Items, LessonNumber) unlike the rest.
- *Pagination*: Almost none. persons/{personId}/tasks takes pageNumber/pageSize; folder/{folderId}/files takes page_number/page_size/order_by; users/me/feed and recentmarks take limit; thread comments take fromCommentId/limit. Range endpoints are paged by date instead (proxiAPI splits long ranges into chunks). Legacy .aspx pages paginate with &page=N read from the <div class="pager">.
- *Notes*: JSON throughout the API; errors are 200/4xx with {type, description} (type camelCase) or an HTML error page (parse <div class="error__description">). Mark values are strings ('5', '4', 'Н', can be non-numeric); mood is a string or object. Work.type distinguishes 'Homework' from other works; lessonLogEntry.status values include Pass, Ill. Reporting-period type/number map to quarters or half-years; year is the school year start.

**Refuted during verification** — rows an extractor proposed that no source carries, kept here so that nobody re-proposes them.

- GET `api.school.mosreg.ru/v2.0/users/{userId}/children` — Not a documented path: the official Swagger v2.0 names this operation GET /v2.0/user/{userID}/children (Children_GetChildrenByUserID, singular 'user'), which is the existing kesha1225 row; smapi's plural form is its own spelling and was never shown to answer.
- GET `api.school.mosreg.ru/v2.0/persons/{personId}/children` — Not a documented path: the official operation is GET /v2.0/person/{personID}/children (Children_GetChildrenByPersonID, singular 'person') — pixwet's spelling, kept as its own row; smapi's plural form is refuted by the Swagger.
- GET `api.school.mosreg.ru/v2/edu-groups/{groupId}/reporting-periods-group` — The official Swagger v2.0 has GET /v2.0/edu-groups/{eduGroup}/reporting-period-group (ReportingPeriods_GetGroupReportingPeriodsGroup) — WebMad's spelling, kept as the current row; pixwet's 'reporting-periods-group' (and smapi's 'reporitng-period-groups') are misspellings.
- GET `api.school.mosreg.ru/v2.0/edu-groups/{groupId}/{from}/{to}` — Not in the official Swagger; a smapi typo for GET /v2.0/edu-groups/{group}/lessons/{from}/{to} (Lessons_GetByGroupAndPeriod), which is already listed.
- GET `api.school.mosreg.ru/v2/person/search` — The official operation is GET /v2.0/persons/search (Persons_Search, query lastName/firstName/middleName/snils/birthday); pixwet's singular 'person/search' is not a documented path. Replaced by a row from the Swagger.
- GET `api.school.mosreg.ru/v2/persons/{personId}/undone` — The official operation Tasks_ListNotCompletedByPersonId — the one pixwet's docstring cites — is GET /v2.0/tasks/{personId}/undone, already listed from alllexey-dev; pixwet's 'persons/{personId}/undone' contradicts its own citation.
- GET `api.dnevnik.ru/v2/schools/{schoolId}/memberships` — The official operation is GET /v2.0/schools/{school}/membership (Schools_GetSchoolMembership, singular, query schoolMembershipType), already listed from alllexey-dev; yasg1988's plural v2 form was never run (the wrapper calls a missing self._get) and is not a documented path.

**Caveats.**

- Most routes come from reverse-engineered or partner-written clients. The official Swagger could only be read as the Wayback copy of 2021-02-25 (https://web.archive.org/web/20210225084600/https://api.dnevnik.ru/partners/swagger/docs/v2.0): 169 operations, now used to confirm or correct paths (7 client spellings refuted, 25 documented operations added). The live Swagger UI (api.dnevnik.ru/partners/swagger/ui/index) renders an empty 'Partners API' shell and its JSON paths 404, so anything newer than February 2021 is known only from clients: kesha1225's 2025 rewrite kept the same paths and SiroXYZ's May 2026 proxy exercises about 25 of them.
- api.school.mosreg.ru / login.school.mosreg.ru are RETIRED (Московская область moved to the МЭШ-based «Моя школа» on 1 September 2023). Rows that the official Swagger documents were moved to api.dnevnik.ru (current); the rest of that host's rows — mostly the /mobile/v6.0 app API — are kept as legacy history. Several of smapi's paths carry typos as written (shcedules, reporitng-period-groups, thematic-mmarks, persons{person_id}); the corrected spelling is given.
- The v1 rows from yasg1988/pydnevnikruapi-extended cannot have run as published (the class calls self._get, which pydnevnikruapi 0.2.0 does not define); treat them as guesses by that author.
- Version prefixes /v2 and /v2.0 are used interchangeably by different clients against the same host; /v1 appears only in a 2015 gem and the unrun wrapper. /mobile/v2 (2020) is superseded by /mobile/v6 and /mobile/v6.0 (2022–2023); the official app has moved on since (10.x in 2025) and its current mobile paths are not in any public client.
- Only one client (SiroXYZ/DnevnikRu_proxiAPI) reports rate limiting: HTTP 429 and 433, handled with retries and a 100-request burst pause. No numbers for the limit itself.
- Token acquisition depends on hard-coded third-party client_ids (<redacted>, <redacted>, and the mobile app's <redacted>) that Дневник.ру can revoke at any time; the consent step already being granted for them is what lets the scripted login skip the 'Разрешить' button.
- Regions that only allow Госуслуги (ЕСИА) sign-in break every login/password client. Workarounds in code: copying the DnevnikAuth_a / DnevnikAuth_l cookies from a browser session (SiroXYZ), region-branded password forms login.dnevnik.ru/login/esia/{region} (WebMad, ragevna), and dnevnikru-aio's playwright run through the Госуслуги password form (no 2FA).
- The cookie-authenticated web endpoints on dnevnik.ru (/api/v2/marks/school/…, /api/posts/…, /currentprogress/…, schools.dnevnik.ru/*.aspx) are scrapes of the web app and can change without notice; several were last exercised in 2021–2022.
- Санкт-Петербург's own diary (dnevnik2.petersburgedu.ru) is a different platform and is not covered here; Дневник.ру applies to Petersburg only for schools contracted to it.
- pykpt/smapi (the source of most api.school.mosreg.ru v2.0 rows) cannot send a request that carries a body, query parameters or a custom version: its @processing decorator is def wrapper(self, arg), so every call with data=, params= or v= raises TypeError before anything is sent. Rows from it that need those (ESIA, POSTs with bodies, user/schedule, by-oktmo, folder files) are written-never-run.
- pixwet/SchoolMosregRuAPI's mobile client looks up three misspelled keys (getSubjectDetailds, getLessonDetailds, getMarksDetailds); METHODS.get() returns '' and the request goes to the API root, so those three paths come only from its table.
- The reporting-period group of a class has three spellings in code: reporting-period-group (WebMad, api.dnevnik.ru v2.0, a bot that ran), reporting-periods-group (pixwet) and reporitng-period-groups (smapi typo). pixwet also appends /edu-groups to lesson-log-entries/lesson/{lesson}/person/{person} against its own docstring; that variant is not listed.
- From 1 September 2026 a first wave of regions (reported as 20: Воронежская, Астраханская, Свердловская, Оренбургская, Еврейская АО, Краснодарский край, Ростовская, Челябинская and others) switched to the federal ТОР «Моя школа» («Госуслуги Моя школа», ESIA-only, no public API). For a school in such a region Дневник.ру stops being the diary and every route here stops returning its data; check the region against support.dnevnik.ru's per-region ЕСИА guides before relying on it.
- Password sign-in is being pushed out in favour of Госуслуги (kesha1225 issue #16, 2024-09-24) and the live login form shows a captcha; scripted login/password clients (kesha1225, paracosm17, I-or-not-I) should be expected to fail for many accounts. The robust token paths are the interactive browser implicit grant and, for a registered partner, the documented /authorizations/esia/v2.0 flow.
- The criteria-journal operations (edu-group/{group}/…/criteria-marks*, criteriajournalsections/many, criteriajournal/finalmark) describe СОр/СОч, Kazakhstan's summative assessments shared with Kundelik.kz; they are documented on api.dnevnik.ru but are marked uncertain and are probably empty for Russian schools.
- Token lifetime is finite: the documented token response carries expiresIn and refreshToken, contrary to the clients' habit of treating the implicit-grant token as permanent.
