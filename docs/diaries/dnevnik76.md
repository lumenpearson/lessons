# «Дневник76» — Ярославская область, until 2024

*Part of [the electronic diaries of Russia’s regions](../diaries.md). Verification: extracted, checked against the code, and dated. Confidence of the whole: medium. Nothing here has been tried against the live service.*

**A regional diary that stopped being the region's diary on 2 September 2024.** «Региональный
интернет-дневник v4.1» at `my.dnevnik76.ru`, run by Zavolga.Net, served Ярославская область until
the region moved to the ЭлЖур-based «Образование-76» at `school.yarcloud.ru` on 16 September 2024
— which in turn gave way to «Госуслуги Моя школа» on 1 September 2026. The old host did not go
dark: the Wayback Machine shows it serving its login page into July 2025. Every route below is
legacy or uncertain, and the page exists so that its two clients on GitHub are not mistaken for a
way into the region today.

**It never had an API.** It was a server-rendered Django site with a form login, its own
Госуслуги sign-in at `/esia/login/`, and a lock after too many failed attempts; the clients scraped
its pages, and the one JSON answer in the whole table is an unread-message counter. Half the rows
come from the Wayback Machine's list of captured URLs rather than from a client, and are marked
uncertain for that reason. The paid mobile app must have talked to something, but nothing shows
what.

**Signing in.**

*Django form login (bvp/dnevnik76-api; the site's own form)* — token carried as cookie: Django session cookie held in the jar (name not written in the code; Django default is sessionid, CSRF cookie csrftoken); form field csrfmiddlewaretoken on the POST. Lifetime: Unknown; no refresh logic — the client simply logs in again. Refresh: None; re-run Login().

1. NewClient: create a cookie jar (publicsuffix) and pre-set cookie items_perpage=1000 (Domain my.dnevnik76.ru, Path /); build an http.Client with InsecureSkipVerify: true
2. NewClient also always calls GET /ajax/school/{region_id}/?login=true (public, via Go's default http client, not the jar) to look up the school name; GET /ajax/kladr/?login=true (GetRegions) is a separate public helper the login flow never calls
3. Login: GET https://my.dnevnik76.ru/accounts/login/ and read .login__form > input[name='csrfmiddlewaretoken'] (was #login_form before 2020-10-12); the CSRF cookie lands in the jar
4. POST https://my.dnevnik76.ru/accounts/login/ as application/x-www-form-urlencoded with next='', csrfmiddlewaretoken, username='{login}@{school_id}', fake_username='{login}', password, school='{school_id}', submit='' and headers Referer: https://my.dnevnik76.ru/accounts/login/, Host: my.dnevnik76.ru, Origin: https://my.dnevnik76.ru, Content-Type: application/x-www-form-urlencoded
5. Go's client follows the redirect; the session cookie is now in the jar (response body ignored)
6. getCurrentInfo: GET /homework/ to establish context: class name from #auth_info > #role, class_id from body onload loadSubjects('/ajax/subj/{id}/', true), school year from #eduyear > #curedy; a parse failure here is the only failure signal of the login
7. Switch school year with SetCookie('edu_year', '{YYYY}') (empty = current), which re-runs getCurrentInfo (re-reads /homework/)

   No captcha, SMS or device token on this flow. Credentials are school-issued logins (e.g. 8 digits, 08331111) plus a password; the site's own JS (common.js loginToSite, archived 2020-11-15) builds username='{fake_username}@{school_id}' from the school_id cookie set by the picker, dropping everything up to the first '.' if the typed login has one, and stores the typed login in a fake_username cookie for 365 days. Failed attempts lock the account: the login redirects to /accounts/login/?attempts_limit=true with «Превышено число неудачных попыток входа! Учетная запись временно заблокирована, попробуйте позже.» (captured 2022-07-01). From 22.09.2015 access from mobile devices was restricted to the paid app (dnevnik76.ru news, 09.10.2015); bvp's Go default User-Agent worked, a mobile browser User-Agent may be refused. The client disables TLS verification (InsecureSkipVerify: true) for the jar client only; the public ajax helpers use http.Get. Form unchanged in the last capture (2025-07-11): hidden csrfmiddlewaretoken, next, submit, username (id_username), school (id_school); visible fake_username, password.

*Browser login via Selenium (maxxig/dnevnik76_telegram_notifier)* — token carried as cookie (browser session). Lifetime: Per run; the README's crontab runs main.py every 10 minutes and each run logs in afresh.

1. Headless Chrome opens https://my.dnevnik76.ru/accounts/login/
2. Click the first div.custom-select__selected and pick //div[contains(@data-value,'{region}')] (e.g. 76000001000/3)
3. Click the second div.custom-select__selected and pick //div[contains(@data-value,'{school}')] (e.g. 760218)
4. Click div#continue-button
5. Type the login into input#id_fake_username and the password into input#id_password, click input[type=submit]
6. Browse /homework/ and /marks/current/{selector}/list/ in the same browser session

   Sleeps 1–3 s between steps. The picker values are '{code}/{level}' (level ≥ 3 lists schools); picking a school GETs /ajax/current_addr/frontend/{school_id}/ and sets cookie school_id (365 days); on submit the page's loginToSite() fills the hidden username '{login}@{school_id}' and school fields (common.js, archived) — no longer an inference.

*ЕСИА sign-in on the old site (my.dnevnik76.ru/esia/login/)* — token carried as cookie: the same Django session, presumably.

1. GET https://my.dnevnik76.ru/esia/login/ — the «Войти через Госуслуги» tab on /accounts/login/ and «Войти через Госуслуги» on the landing page (both in the 2025-07-11 capture)
2. Redirect to esia.gosuslugi.ru and back (not captured; no client implements it)

   Existed alongside the form login (logo_gosuslugi.png from 2016, rid_esia_2019.pdf referenced); the landing page also says a password can be requested through the Госуслуги service «Получение информации о текущей успеваемости обучающегося». No client uses it; steps after the redirect are unknown.

*Successor ЕСИА sign-in (school.yarcloud.ru, ЭлЖур) — documents only, not this platform* — token carried as unknown (no client code); ЭлЖур-based.

1. Open https://school.yarcloud.ru
2. Choose sign-in through Госуслуги (ЕСИА) — «Вход в новый интернет-дневник для всех пользователей возможен через авторизацию в ЕСИА (учетная запись на ЕПГУ)»

   Old my.dnevnik76.ru logins/passwords do not work there (school notices). Some schools reportedly still issued individual logins (promodoc.ru). From 01.09.2026 the region's diary moves to «Госуслуги Моя школа» (verified Госуслуги account required; parents create child accounts for under-14s). Both belong to other platforms.

**Headers the clients send.**

| Header | Value | Why |
| --- | --- | --- |
| `Referer` | https://my.dnevnik76.ru/accounts/login/ | Set on the login POST; Django's CSRF check over HTTPS rejects a POST without a same-origin Referer |
| `Origin` | https://my.dnevnik76.ru | Set on the login POST alongside Referer |
| `Content-Type` | application/x-www-form-urlencoded | Form login |
| `Host` | my.dnevnik76.ru | Set explicitly by bvp on the login POST |
| `Cookie: items_perpage` | 1000 (UI offers 10, 20, 30, 50) | Page size of server-rendered lists (homework, messages); set so that one page holds everything, since the client does not paginate; bvp's tests reset it to empty |
| `Cookie: edu_year` | YYYY or empty | Selects which school year pages show; empty means current |
| `User-Agent` | a desktop browser or a non-mobile client string (bvp used Go's default) | From 22.09.2015 the operator restricted mobile-device web access to the paid app (2015 news); a mobile browser User-Agent may be refused. Not verified against the server |
| `Cookie: school_id` | six-digit school id | Set by the login page's picker (365 days) and read by loginToSite() to build username; also preselects the school via /accounts/login/?school_id=. A scripted client sends username and school in the POST body instead |

**Captcha and second factor.** None on my.dnevnik76.ru; failed attempts trigger a temporary account lock (/accounts/login/?attempts_limit=true). The successors require ЕСИА (Госуслуги) with whatever 2FA the user's Госуслуги account has.

No rate limiting or User-Agent handling in any client; bvp uses Go's default UA, maxxig a real headless Chrome. All data is scraped from HTML with CSS selectors, so any markup change breaks the clients (bvp already had to change the login selector once, in 2020). As of 2026 no login to my.dnevnik76.ru serves any school: accounts stopped being maintained on 02.09.2024, even though the host kept answering at least until 2025-07-11.

**Formats.**

- *Dates*: Russian long-form text, no ISO: «17 декабря 2018 г.», with time «17 декабря 2018 г. 18:09», day header «Понедельник (17 декабря 2018 г.)», period header «с 1 сентября 2018 г. по 31 октября 2018 г.», school year «2018-2019 учебный год». bvp parses with github.com/bvp/russiantime; maxxig replaces month names with numbers and uses '%d %m %Y г.'. Times are local (Europe/Moscow).
- *Ids*: Numeric: region_id KLADR-like 11 digits (76000001000; picker data-value adds '/3'), school_id 6 digits (760215), class_id and course_id integers from select options, message_id integer (checkbox value), login 8 digits (08331111) qualified as '{login}@{school_id}' in the form and in teacher links. Period slugs: month9..month12, month1..month8 and edurng{N} (term, e.g. edurng11385), plus week. Grades are integers; averages with a comma decimal; non-numeric marks exist (maxxig uppercases them). Picker values in the 2020 login page are '{code}/{level}' (level 2 district/city, 3 town, 4 village); level ≥ 3 lists schools.
- *Pagination*: Server-rendered pager: div.pager > span.page (span.page_next for next), span.page_remark present when there is more than one page; ?page=N on /messages/input/; page size from cookie items_perpage (10/20/30/50 in UI, bvp sets 1000, maxxig picks 50 in select#items_perpage). No JSON pagination.
- *Notes*: Everything except /ajax/messages_count/ is HTML; /ajax/* returns <select> fragments (old family) or custom-select div fragments (/frontend/ family). 'current' in /marks/current/ means the current school year, so /marks/current/month9/ is September of that year. Public file links /files/link/{hash}/ serve the file body directly.

**Caveats.**

- Status as of 2026-09-24: my.dnevnik76.ru has not been the region's diary since 02.09.2024 (school notices), but it did not vanish: the Wayback Machine captured /, /accounts/login/, /stat/upload/ and /school/registration/ answering 200 with an unchanged working login form monthly until 2025-07-11, and /ajax/current_addr/frontend/760403/ on 2025-05-23. Nothing after 2025-07-11 was captured and the host cannot be probed from here, so whether it answers today is unknown. Whatever it answers, no school keeps data there since 2024-09, so every route is legacy.
- The region has moved twice since: to ГИС «Образование-76» (school.yarcloud.ru, ЭлЖур) from 16.09.2024, and to ТОР «Госуслуги Моя школа» from 01.09.2026. Neither is this platform; their APIs belong to the ЭлЖур and «Моя школа» records.
- Only two real clients exist, both unmaintained: bvp/dnevnik76-api (Go, archived 2025-03-28, last commit 2023-10-05) and maxxig/dnevnik76_telegram_notifier (Selenium, last commit 2023-10-10). There was no official or JSON API; this is HTML scraping of a Django site, and the only JSON response is /ajax/messages_count/.
- The paid mobile app (ru.dnevnik76.electronicdiary, App Store id1257563724) must have talked to some API, but no client, archive capture or document shows it: no api.* host was archived under dnevnik76.ru and the APK could not be downloaded here. That surface is unknown, not absent.
- Rows sourced from the Wayback CDX (files, messages output/reply/mass, conflist, advert, marks 'less', the 2011/2012 generations) are known from captured URLs and login redirects only; their markup and any POST behind them are unknown, hence 'uncertain' where only a redirect was seen.
- /schedule/, /stat/ and /settings/ are known only as links in a browser extension (and /schedule from 2011); /messages/new/?to= only as an href on /teachers/; /marks/current/{period}/date/ is built but never parsed.
- No write operations (sending messages, marking read, settings, file upload) appear in any client.
- Session cookie names are not written in the clients; sessionid/csrftoken are an inference from the Django csrfmiddlewaretoken field.
- bvp calls /messages/input, /ajax/subj/{id} and (from GetMarksPeriods) /marks/current/{period}/note without the trailing slash the site's own links use; captures show the site answering 301 to the slashed form (e.g. /messages/input/19077 -> 301).
- Login success is never checked directly by bvp; failed attempts can lock the account (attempts_limit), so a client retrying bad credentials will lock the user out.
- Mobile-device web access was restricted to the paid app from 22.09.2015; how the server told a mobile browser apart (User-Agent presumably) is not documented.
